# ADR-0002: Configuration

- Status: accepted
- Date: 2026-10-17

## Context

Every host is deployed through Nix; secrets come from sops as files. The convention of the author's other products is a TOML file generated by a NixOS module, never hand-written, with secrets referenced by path (genkan ADR 0002, kekkai ADR 0016).

## Decision

- One TOML file per component, generated by the NixOS module through `pkgs.formats.toml`, passed as `hanko run <file>`. Unknown keys are an error. `hanko check <file>` validates it; the module runs the check at build time.
- **No secret in the file**: the TSIG key, the ACME account key and the CA key are paths. The account key is the only secret hanko creates (ADR-0003).
- Shape of the oneshot's file (illustrative; `hanko-ca`'s own file is in ADR-0004):

```toml
[acme]
directory = "https://acme-v02.api.letsencrypt.org/directory"   # staging in tests
account_key_file = "/var/lib/hanko/account.key"                # created on first run
accept_terms = true                                            # the CA's terms of service, accepted explicitly

[dns]
nameservers = ["203.0.113.10:53", "[2001:db8::10]:53"]        # every public NS, by address
tsig_key_file = "/run/secrets/hanko-tsig"                     # "<name>:<base64 secret>", one line
propagation_timeout = "120s"

[internal]                                                     # v1, absent in v0
ca = "[fd12:3456:789a::1]:4900"                                # hanko-ca over the overlay

[[certificates]]
name = "home"
issuer = "acme"
hosts = ["*.uchi.example.org", "uchi.example.org"]
reload = ["genkan.service"]

[[certificates]]
name = "cv"
issuer = "acme"
hosts = ["cv.example.org", "cv.soto.example.org"]
reload = ["genkan.service"]

[[certificates]]                                               # v1
name = "api"
issuer = "internal"
spiffe_id = "spiffe://uchi.example.org/vm/api"
```

- A certificate's `name` is the directory under the state directory where its files land (ADR-0005). Names are unique, lowercase `[a-z0-9-]`.
- `reload` lists the systemd units to reload (`systemctl reload`, falling back to restart when the unit has no `ExecReload`) after that certificate changed. Reloading is hanko's job, not the consumer's module's, so that the consumer never has to know when a file changed (genkan ADR 0003).
- Issuer-specific keys live under the issuer's table (`[acme]`, `[internal]`); per-certificate keys are `issuer`, `hosts` or `spiffe_id`, and `reload`. `check` rejects a certificate whose keys do not match its issuer, and an issuer table that no certificate uses.
- **NixOS module shape**, mirroring the file one to one, with a timer option:

```nix
services.hanko = {
  enable = true;
  timer = "hourly";                        # OnCalendar
  acme.directory = "https://acme-staging-v02.api.letsencrypt.org/directory";
  acme.acceptTerms = true;
  dns = { nameservers = [ … ]; tsigKeyFile = config.sops.secrets.hanko-tsig.path; };
  certificates.home = { hosts = [ "*.uchi.example.org" "uchi.example.org" ]; reload = [ "genkan.service" ]; group = "genkan"; };
};
```

  `group` is the module's, not the file's: it decides who may read the files (ADR-0005). The module creates the certificate directories, the timer, the `OnFailure=` hook option and the `restartTriggers` on the file (ADR-0001).

## Alternatives considered

- **Flags or environment variables.** Unreadable from a module, and secrets would leak into `ps`. Rejected.
- **Letting consumers list their own `reloadServices`**, as `security.acme` does. It spreads the reload wiring over every consumer module; one list per certificate in hanko's file is simpler and is what genkan expects.
- **One file per certificate.** More files for no gain; the module generates one.

## Consequences

- A unit test deserialises the complete example; the `nixosTest` proves the module's output passes `hanko check`.
- The file is the contract between the module and the binary; `check`'s messages document it.

## Amendment 2026-10-29: no `reload` on internal certificates

`reload` belongs to `acme` certificates only; `check` refuses it on an `internal` one, whose
consumers reload their files themselves ([ADR-0013](0013-consumers-reload-internal-certificates.md)).
The example above lost its `api` reload accordingly.
